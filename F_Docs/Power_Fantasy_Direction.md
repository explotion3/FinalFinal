# 爽游化差异方向草案

## 1. 核心定位
项目差异化方向暂定为：

```text
武侠爽文式成长 + Roguelike 卡牌构筑 + 局内高倍率爆发
```

目标不是做“更大数字的传统爬塔卡牌”，而是让玩家在一局内把角色、卡牌和战斗引擎养成离谱武学体系。

传统爬塔卡牌偏向：
* 精算
* 克制
* 资源紧张
* 每张牌谨慎选择

本项目希望强化：
* 成长
* 爆发
* 碾压
* 连锁反应
* 战斗中突破
* 越来越离谱的局内构筑

爽感应来自玩家亲手养成的构筑，而不是系统单纯赠送数值。

## 2. 已确定原则

### 2.1 角色成长是主轴
Run 的成长主轴从“牌组变强”扩展为“角色变强”。

第一批通用角色成长属性确定为：
* `根骨`
* `悟性`
* `杀意`

这三项不替代现有 `Attack / Defense / VitalShare / StressCap` 等基础属性，而是在 Run 内提供基础面板与成长效率修正，放大角色原本定位。

### 2.2 根骨
定位：身体底子、承压、防御收益。

第一版映射：
```text
每 1 点根骨：
生命份额 +6
防御力 +2
压力上限 +1
```

根骨直接提高基础面板，因此所有按防御力结算的护盾牌会自然受益。

### 2.3 悟性
定位：学习速度、卡牌成长、构筑改造效率。

第一版映射：
```text
每 1 点悟性：
突破值获取 +10%
```

卡牌进化候选质量、事件中额外成长选项概率、重掷候选等内容保留为后续扩展，不进入第一版硬协议。

悟性不直接决定“战后谁能拿到卡牌成长事件”。否则玩家若想单独养成某名角色，会被迫把大量点数投入悟性来抢成长候选，导致悟性过于重要。

推荐成长入口：
```text
每名角色拥有局内突破槽
战斗中使用该角色卡牌、完成角色定位行为、战斗胜利、事件或奖励都能获得突破值
突破槽满后触发该角色自己的卡牌进化 / 突破选择
悟性只提高突破值获取速度
```

### 2.4 杀意
定位：攻击、收割、连杀爆发。

第一版映射：
```text
每 1 点杀意：
攻击力 +2
暴击率 +1%
暴击伤害 +3%
```

杀意直接提高基础输出面板，因此所有按攻击力结算的攻击牌会自然受益。

### 2.5 角色升级成长选择

角色升级不再拆成多个连续操作。
每次角色升级只触发一次成长三选一，候选项混合属性成长与卡牌进化。

```text
战斗中获得突破值 -> 突破槽满 -> 角色升级 -> 成长三选一
```

成长候选类型：

* 属性成长：`根骨 / 悟性 / 杀意 +1`，强化角色本体
* 卡牌进化：基础卡 -> 进化卡，或进化卡 -> 绝学卡，改变招式形态
* 特殊成长：后续保留，例如增加强化槽、提升槽级、临界相关成长；第一版暂缓

第一版候选生成口径：

* 每次升级生成 `3` 个成长候选，玩家选择 `1` 个
* 至少包含 `1` 个属性成长候选
* 至少包含 `1` 个卡牌进化候选
* 第 `3` 个候选随机生成，可受已进化卡牌、角色当前路线影响

悟性的第一版作用：

* 提高突破值获取速度

悟性的后续可扩展作用：

* 提高成长候选质量
* 提高已培养卡牌出现在进化候选中的概率
* 提高绝学化候选出现率
* 后续可扩展为重掷候选或四选一

示例：

```text
霍断岳升级，选择一项成长：

1. 根骨 +1
   提高压力上限，扩大临界窗口。

2. 杀意 +1
   提高霍断岳攻击牌的爆发能力。

3. 裂锋 -> 裂锋·破势
   裂锋获得更高削韧，并在造成 Break 时获得刀势。
```

设计重点：

* 升级只做一次选择，减少操作负担
* 属性成长强化角色本体，卡牌进化改变招式形态
* 属性成长需要清楚展示实际收益，避免被卡牌进化完全压过
* 进化候选优先从该角色所属 `RunCardInstance` 中生成
* 绝学化应只在卡牌已进化，并满足角色等级、属性、使用次数或槽位成长等条件后出现

### 2.6 压力改为临界爆发

保留压力系统的主题位置，但不再把压力满直接定位为纯惩罚。

建议方向：

```text
受伤或高压行为 -> 压力上升
当前压力 >= 临界阈值 -> 进入临界
临界期间 -> 获得角色专属爆发收益或可使用临界牌
临界期间继续受压 / 临界处理失败 -> 进入崩溃判定
```

临界不是崩溃前的倒计时，而是高压状态下的爆发窗口。
玩家应该能在临界期间主动利用角色特性反打、稳压或完成关键击杀。

#### 2.6.1 临界与崩溃阈值

第一版临界阈值：

```text
临界阈值比例 = 90%
临界阈值 = ceil(压力上限 × 90%)
崩溃阈值 = 压力上限
```

这个数值后续应放入配置，便于在 `80% ~ 95%` 区间调试。

推荐使用向上取整，避免低压力上限角色过早进入临界。

示例：

```text
压力上限 10 -> 临界阈值 9，崩溃阈值 10，临界窗口 1
压力上限 13 -> 临界阈值 12，崩溃阈值 13，临界窗口 1
压力上限 20 -> 临界阈值 18，崩溃阈值 20，临界窗口 2
压力上限 30 -> 临界阈值 27，崩溃阈值 30，临界窗口 3
```

根骨提高压力上限后，会同时推迟临界、推迟崩溃，并扩大临界阈值到崩溃阈值之间的可操作空间。

#### 2.6.2 压力状态机

压力状态暂定拆分为：

```text
Normal
- 当前压力 < 临界阈值
- 角色处于普通承压状态

Critical
- 当前压力 >= 临界阈值
- 首次越过临界阈值时进入
- 获得角色专属临界收益或解锁临界牌
- 可以通过降低压力退出

Collapse
- 临界期间继续获得压力
- 或临界处理失败
- 或其他规则明确要求进入崩溃
```

首次越过临界阈值时，优先进入 `Critical`，不在同一次压力事件中直接进入 `Collapse`。

#### 2.6.3 越过临界保护

越过临界保护用于避免单次高额压力事件直接跳过临界窗口。

规则口径：

```text
若一次压力变化同时越过临界阈值和崩溃阈值：
优先进入临界
当前压力可被钳制到崩溃阈值
本次压力事件不直接触发崩溃
临界期间再次受压、或后续规则判定失败时，才进入崩溃判定
```

这个保护只保证玩家至少获得一次临界窗口，不保证临界状态安全。
如果玩家进入临界后继续承受压力，就应该面对崩溃风险。

#### 2.6.4 临界退出方式

临界必须有明确退出方式，否则它会退化成延迟惩罚。

第一版建议：

```text
当前压力降低到临界阈值以下 -> 退出临界，回到 Normal
当前战斗结束 -> 清除临界状态标记
战斗结束后的压力保留或回落规则，仍按后续压力系统总规则决定
```

后续可扩展的退出方式：

```text
使用稳定类卡牌降低压力
释放角色奥义后退出临界
造成 Break 后降低压力并退出临界
击杀敌人后降低压力并退出临界
触发治疗、护盾或心法效果后退出临界
```

#### 2.6.5 临界期间的崩溃判定

临界期间继续获得压力时，默认进入崩溃判定。
但不建议把“临界期间只要再获得 1 点压力就必定崩溃”写死为唯一规则。

崩溃判定应保留可配置和可被成长系统修正的空间：

```text
根骨较高：临界期间第一次继续受压可被抵消
叶半夏相关效果：临界期间获得稳心，抵消下一次压力
遗物 / 心法：每场战斗第一次进入临界时降低压力或获得保护层
魔功 / 高风险构筑：临界收益更强，但临界期间受压更容易崩溃
```

设计重点：

* 压力接近满值时先给玩家一个爆发窗口，而不是立刻让角色失效
* 崩溃保留为临界处理失败后的失控惩罚
* 临界收益应按角色区分，例如削韧爆发、治疗爆发、抽牌重排、击杀增伤
* 根骨提高压力上限后，会同时提高承压能力和临界可操作空间
* 悟性可提高临界可控性
* 杀意可强化临界输出
* 首次越过临界阈值时优先进入临界，避免单次压力事件直接跳过临界窗口进入崩溃
* 临界状态要鼓励玩家主动利用，而不是单纯等待惩罚发生

## 3. 第一版竖切

第一轮不要同时实现所有方向。建议先做：

```text
角色突破槽 -> 角色升级 -> 成长三选一 -> 立即应用属性成长或卡牌进化
```

最小闭环：

* Run 内保存每名角色的局内突破值
* 突破值获取方式可按角色定位不同配置，例如使用所属卡牌、造成 Break、有效治疗、抽牌、击杀、承压
* 悟性只影响该角色突破值获取速度
* 突破槽满后触发角色升级
* 角色升级时生成 `3` 个成长候选，至少包含 `1` 个属性成长和 `1` 个卡牌进化候选
* 玩家选择 `1` 个成长候选
* 若选择属性成长，立即提高该角色的 `根骨 / 悟性 / 杀意`
* 若选择卡牌进化，从该角色 `RunDeck` 中选择或生成可进化牌，并更新对应 `RunCardInstance`
* 进化后卡牌名称、数值或规则文本发生变化
* 若被进化的卡牌当前在手牌中，立即刷新当前手牌卡面和效果
* 若被进化的卡牌不在手牌中，更新卡牌实例，之后抽到就是进化后的版本

第一版目标是验证：

```text
玩家能否在角色升级时只做一次选择，并立刻感受到角色或卡牌变强。
```

## 4. 可保留的后续方向

### 4.1 卡牌绝学化

卡牌绝学化是本方向中最重要的卡牌成长系统之一。
它的目标不是简单提高数值，而是让玩家在一局 Run 中把普通招式逐步练成核心武学。

后续完整卡牌成长可以拆成三件事：

```text
强化珠：提供卡牌细节强化
进化：改变卡牌形态、机制方向或槽位结构
绝学化：高阶进化，使卡牌成为可围绕构筑的核心牌
```

#### 4.1.1 卡牌成长作用于实例

卡牌成长不修改静态 `CardDefinition`，而是作用于 Run 内的 `RunCardInstance`。

每张 Run 内卡牌至少保留：

```text
BaseCardId：原始卡牌身份
CurrentCardId：当前卡牌形态
GemSlots：强化槽结构
EquippedGems：已镶嵌强化珠
```

例如：

```text
BaseCardId = 裂锋
CurrentCardId = 裂锋·血战绝式
```

这样可以保留“普通招式被练成绝学”的成长轨迹。

#### 4.1.2 强化珠与强化槽

第一版不设置强化珠背包。

玩家获得强化珠时，需要立即选择一张可用卡牌镶嵌，或者跳过换取补偿。

强化槽采用槽级限制，而不是占用多个槽位：

```text
一个强化槽只能放一个强化珠
强化槽有槽级
强化珠有珠阶
强化珠只能放入槽级 >= 珠阶的槽
```

示例：

```text
1级槽：可放 1阶珠
2级槽：可放 1阶珠 / 2阶珠
3级槽：可放 1阶珠 / 2阶珠 / 3阶珠
4级槽：可放 1阶珠 / 2阶珠 / 3阶珠 / 4阶珠
```

珠阶代表镶嵌门槛，珠级代表强化程度。

```text
珠阶：决定需要几级槽才能镶嵌
珠级：决定同一种珠子的强化强度
```

#### 4.1.3 强化珠合成

同一张卡牌上允许镶嵌多个同名同级强化珠。

当同一张卡牌上拥有 3 个同名同级强化珠时，自动合成为 1 个更高珠级的同名强化珠。

```text
3 个 锋利珠 Lv1 -> 1 个 锋利珠 Lv2
```

合成后：

```text
珠阶不变
仍然只占一个强化槽
仍然需要相同槽级
```

第一版建议珠级上限先做到 Lv2，后续再考虑 Lv3。

#### 4.1.4 珠子示例

```text
锋利珠
珠阶：1
Lv1：攻击牌伤害 +10%
Lv2：攻击牌伤害 +30%

破势珠
珠阶：2
Lv1：削韧 +1
Lv2：削韧 +2

回气珠
珠阶：3
Lv1：若本牌造成 Break，回复 1 AP
Lv2：若本牌造成 Break，回复 1 AP，并抽 1 张牌
```

AP、抽牌、费用降低、额外触发等行动经济类珠子必须谨慎设计。
高阶珠不应简单翻倍，而应增加附加收益或限制触发条件。

#### 4.1.5 进化与槽位结构

进化不只意味着卡牌效果变强，也可以改变强化槽结构。

第一版允许三类进化方向：

```text
效果进化：卡牌效果增强，槽位小幅提升
多槽进化：卡牌效果变化较小，但槽位数量增加
高槽进化：卡牌效果变化较小，但获得更高级槽位
```

示例：

```text
裂锋
1 AP
造成伤害，削韧 2
槽位：1 / 1

裂锋·破势
效果进化
造成伤害，削韧 3
若造成 Break，获得 1 刀势
槽位：2 / 1

裂锋·藏锋
多槽进化
效果基本不变
槽位：2 / 2 / 1

裂锋·纳元
高槽进化
效果基本不变
槽位：3 / 1
```

这种设计让进化选择不只是在“立即变强”和“数值更高”之间取舍，也可以选择更高的后续成长上限。

#### 4.1.6 绝学化

绝学化是高阶进化。

绝学化后的卡牌应该满足至少一项：

```text
拥有更强的机制方向
拥有更高或更特殊的槽位结构
与临界、Break、AP、角色资源产生强绑定
成为玩家可以围绕构筑的核心牌
```

示例：

```text
裂锋·血战绝式
1 AP
造成伤害，削韧
若霍断岳处于临界，本牌额外触发一次
槽位：3 / 2 / 1
```

绝学化不要求每张卡都支持。
第一版建议只让少数核心卡支持绝学化。

#### 4.1.7 第一版约束

第一版先采用以下约束：

```text
不设置强化珠背包
获得珠子时立即镶嵌或跳过
一个槽放一个珠
槽级限制珠阶
同卡三合一提升珠级
合成后珠阶不变
珠级上限先做到 Lv2
基础卡通常只有 1级槽
进化卡可以出现 2级槽
槽位型进化可以出现 3级槽
绝学卡才考虑稳定出现 3级槽或少量 4级槽
```

强化珠负责细节强化。
进化负责改变卡牌方向。
绝学化负责让卡牌成为构筑核心。
### 4.2 AP 成长与聚合消费
AP 可以在一局内成长，但必须配套能聚合消费的设计，避免后期每回合只是机械打很多张低费牌。

可考虑：
* 高费爆发牌
* X 费牌
* 消耗全部 AP 的终结牌
* AP 转化为其他爆发资源
* 连击阈值后的自动追击
* 多余 AP 自动转化为收益

设计原则：
```text
AP 变多后，玩家应该更能爆发，而不是更累。
```

### 4.3 连锁反应构筑
让战斗爽感来自一串触发，而不只是单次大数字。

可考虑：
* 破防触发追击
* 击杀触发抽牌或返 AP
* 毒伤触发扩散
* 获得护盾触发反击
* 使用同类卡牌第 N 次触发额外效果
* 绝学牌击杀后重复一次或追加全体伤害

### 4.4 事件与奖励改为强化构筑
事件、商店、奖励节点不只给资源，而是提供高影响的改造机会。

可考虑：
* 选择一张牌获得词条
* 选择一个角色立即获得突破值
* 永久增加每回合 AP
* 将某张牌推进到下一进化阶位
* 获得强力副作用，例如伤害翻倍但每战开局受伤

### 4.5 敌人与 Boss 检查爆发窗口
敌人设计不应频繁禁止玩家构筑。

不推荐常用：
* 禁止抽牌
* 禁止连击
* 禁止复制
* 强行增加所有卡牌费用

推荐方向：
* 允许玩家爆发，但要求选择正确窗口
* 普通敌人提供爽感舞台
* 精英敌人检查流派短板
* Boss 改变爆发节奏，而不是封死构筑

## 5. 第一版范围与暂不实现内容

本章节用于收束 `Power_Fantasy_Direction.md`，避免继续扩展新系统。第一版目标不是做完整爽游体系，而是验证“角色成长 + 卡牌实例进化”的最小闭环。

### 5.1 第一版验证目标

第一版只验证：

```text
玩家能否在一次 Run 中：
角色通过升级获得一次成长三选一
属性成长能立刻改变角色基础面板
一张核心卡从基础卡进化为更强形态
若该卡在当前手牌中，手牌能立刻刷新为进化后的卡面和效果
压力能按 Normal / Critical / Collapse 状态机正确流转
临界能提供一次明确的高压窗口，而不是被单次压力事件直接跳过
```
### 5.2 第一版必须包含

```text
角色升级成长三选一
基础属性：根骨 / 悟性 / 杀意
角色突破值获取与悟性加成
少量卡牌进化样例
RunCardInstance 记录 BaseCardId / CurrentCardId
当前手牌卡牌实例即时刷新
压力状态机：Normal / Critical / Collapse
临界阈值：ceil(压力上限 × 90%)
首次越过临界阈值时优先进入 Critical
临界期间继续受压进入崩溃判定
压力降低到临界阈值以下时退出 Critical
```

第一版优先选择一名角色和少量核心卡做完整竖切，不追求三名角色同时完整覆盖。

临界进入第一版，但第一版只实现通用状态机和通用崩溃判定，不实现角色专属临界收益。
### 5.3 第一版暂不实现

```text
完整经脉 / 门派 / 心法 / 魔功系统
角色专属临界收益
临界牌
临界流派遗物与事件
强化珠即时镶嵌
强化珠背包
强化珠自由拆卸与长期库存
强化槽槽级限制珠阶
同卡同名珠三合一升级
珠子套装、洗词条、合成树
少量卡牌绝学化样例
所有卡牌完整进化树
所有角色完整临界分支
复杂 AP 无限循环构筑
每张卡独立熟练度条
```

这些内容可以作为后续扩展，但不进入第一版硬协议。
### 5.4 主要设计风险

```text
属性候选太弱，玩家会永远选择卡牌进化
悟性如果影响候选质量过多，会再次变成必点属性
卡牌进化候选太强，会压过属性成长
战斗中升级弹窗太频繁，会打断战斗节奏
临界收益太强，玩家会故意堆压力
AP 返还类效果容易制造无限循环
```

## 6. 需要避免
* 不要只堆数值；卡牌从 10 伤害变成 100 伤害很快会腻
* 不要让成长太平均；玩家需要感觉自己重点培养了某个角色或某张牌
* 不要用敌人强行禁止玩家爽；可以考验爆发窗口，但不要频繁封锁构筑
* 不要让每回合操作量无限膨胀；AP 成长必须配套高费牌、自动触发或资源转化
* 不要在规则层为单张卡、单个敌人写硬编码特例；成长仍要数据驱动

## 7. 后续设计原则
后续改规则时优先遵守：

* 让玩家感觉自己在养成怪物
* 允许中后期构筑明显失控
* 爽感来自成长兑现，而不是单纯降低难度
* 战斗中突破要有即时反馈
* 卡牌进化要改变名称、卡面、数值或规则文本
* UI 必须清楚展示角色和卡牌为什么变强
* 规则仍保持数据驱动，不为单张卡硬写特例
