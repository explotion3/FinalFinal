# 爽游化差异方向草案

## 1. 核心定位
项目差异化方向暂定为：

```text
武侠爽文式成长 + Roguelike 卡牌构筑 + 局内高倍率爆发
```

目标不是做“更大数字的传统爬塔卡牌”，而是让玩家在一局内把角色、卡牌和战斗引擎养成离谱武学体系。

传统爬塔卡牌偏向：
* 精算
* 克制
* 资源紧张
* 每张牌谨慎选择

本项目希望强化：
* 成长
* 爆发
* 碾压
* 连锁反应
* 战斗中突破
* 越来越离谱的局内构筑

爽感应来自玩家亲手养成的构筑，而不是系统单纯赠送数值。

## 2. 已确定原则

### 2.1 角色成长是主轴
Run 的成长主轴从“牌组变强”扩展为“角色变强”。

第一批通用角色成长属性确定为：
* `根骨`
* `悟性`
* `杀意`

这三项不替代现有 `Attack / Defense / VitalShare / StressCap` 等基础属性，而是在 Run 内提供基础面板与成长效率修正，放大角色原本定位。

### 2.2 根骨
定位：身体底子、承压、防御收益。

第一版映射：
```text
每 1 点根骨：
生命份额 +6
防御力 +2
压力上限 +1
```

根骨直接提高基础面板，因此所有按防御力结算的护盾牌会自然受益。

### 2.3 悟性
定位：学习速度、卡牌成长、构筑改造效率。

第一版映射：
```text
每 1 点悟性：
突破值获取 +10%
卡牌进化候选质量权重小幅提高
事件中出现额外成长选项的概率小幅提高
```

悟性不直接决定“战后谁能拿到卡牌成长事件”。否则玩家若想单独养成某名角色，会被迫把大量点数投入悟性来抢成长候选，导致悟性过于重要。

推荐成长入口：
```text
每名角色拥有局内突破槽
战斗中使用该角色卡牌、完成角色定位行为、战斗胜利、事件或奖励都能获得突破值
突破槽满后触发该角色自己的卡牌进化 / 突破选择
悟性只提高突破值获取速度
```

### 2.4 杀意
定位：攻击、收割、连杀爆发。

第一版映射：
```text
每 1 点杀意：
攻击力 +2
暴击率 +1%
暴击伤害 +3%
```

杀意直接提高基础输出面板，因此所有按攻击力结算的攻击牌会自然受益。

### 2.5 属性点来源
第一版属性点主要来自角色突破。

建议口径：
```text
角色突破槽满 -> 触发突破 -> 获得可分配属性点 -> 后续在角色面板中分配到根骨 / 悟性 / 杀意
```

可保留的额外来源：
* 事件 / 奇遇：提供定向属性点或带代价的属性成长
* 练功房：选择一名角色，获得 `2` 点属性点

科研保留：
* 心法 / 遗物可提供长期属性加成或改变属性获取方式，但不进入第一版基础来源

### 2.6 压力改为临界爆发

保留压力系统的主题位置，但不再把压力满直接定位为纯惩罚。

建议方向：

```text
受伤或高压行为 -> 压力上升
当前压力 >= 临界阈值 -> 进入临界
临界期间 -> 获得角色专属爆发收益或可使用临界牌
临界期间继续受压 / 临界处理失败 -> 进入崩溃判定
```

临界不是崩溃前的倒计时，而是高压状态下的爆发窗口。
玩家应该能在临界期间主动利用角色特性反打、稳压或完成关键击杀。

#### 2.6.1 临界与崩溃阈值

第一版临界阈值：

```text
临界阈值比例 = 90%
临界阈值 = ceil(压力上限 × 90%)
崩溃阈值 = 压力上限
```

这个数值后续应放入配置，便于在 `80% ~ 95%` 区间调试。

推荐使用向上取整，避免低压力上限角色过早进入临界。

示例：

```text
压力上限 10 -> 临界阈值 9，崩溃阈值 10，临界窗口 1
压力上限 13 -> 临界阈值 12，崩溃阈值 13，临界窗口 1
压力上限 20 -> 临界阈值 18，崩溃阈值 20，临界窗口 2
压力上限 30 -> 临界阈值 27，崩溃阈值 30，临界窗口 3
```

根骨提高压力上限后，会同时推迟临界、推迟崩溃，并扩大临界阈值到崩溃阈值之间的可操作空间。

#### 2.6.2 压力状态机

压力状态暂定拆分为：

```text
Normal
- 当前压力 < 临界阈值
- 角色处于普通承压状态

Critical
- 当前压力 >= 临界阈值
- 首次越过临界阈值时进入
- 获得角色专属临界收益或解锁临界牌
- 可以通过降低压力退出

Collapse
- 临界期间继续获得压力
- 或临界处理失败
- 或其他规则明确要求进入崩溃
```

首次越过临界阈值时，优先进入 `Critical`，不在同一次压力事件中直接进入 `Collapse`。

#### 2.6.3 越过临界保护

越过临界保护用于避免单次高额压力事件直接跳过临界窗口。

规则口径：

```text
若一次压力变化同时越过临界阈值和崩溃阈值：
优先进入临界
当前压力可被钳制到崩溃阈值
本次压力事件不直接触发崩溃
临界期间再次受压、或后续规则判定失败时，才进入崩溃判定
```

这个保护只保证玩家至少获得一次临界窗口，不保证临界状态安全。
如果玩家进入临界后继续承受压力，就应该面对崩溃风险。

#### 2.6.4 临界退出方式

临界必须有明确退出方式，否则它会退化成延迟惩罚。

第一版建议：

```text
当前压力降低到临界阈值以下 -> 退出临界，回到 Normal
当前战斗结束 -> 清除临界状态标记
战斗结束后的压力保留或回落规则，仍按后续压力系统总规则决定
```

后续可扩展的退出方式：

```text
使用稳定类卡牌降低压力
释放角色奥义后退出临界
造成 Break 后降低压力并退出临界
击杀敌人后降低压力并退出临界
触发治疗、护盾或心法效果后退出临界
```

#### 2.6.5 临界期间的崩溃判定

临界期间继续获得压力时，默认进入崩溃判定。
但不建议把“临界期间只要再获得 1 点压力就必定崩溃”写死为唯一规则。

崩溃判定应保留可配置和可被成长系统修正的空间：

```text
根骨较高：临界期间第一次继续受压可被抵消
叶半夏相关效果：临界期间获得稳心，抵消下一次压力
遗物 / 心法：每场战斗第一次进入临界时降低压力或获得保护层
魔功 / 高风险构筑：临界收益更强，但临界期间受压更容易崩溃
```

设计重点：

* 压力接近满值时先给玩家一个爆发窗口，而不是立刻让角色失效
* 崩溃保留为临界处理失败后的失控惩罚
* 临界收益应按角色区分，例如削韧爆发、治疗爆发、抽牌重排、击杀增伤
* 根骨提高压力上限后，会同时提高承压能力和临界可操作空间
* 悟性可提高临界可控性
* 杀意可强化临界输出
* 首次越过临界阈值时优先进入临界，避免单次压力事件直接跳过临界窗口进入崩溃
* 临界状态要鼓励玩家主动利用，而不是单纯等待惩罚发生
## 3. 第一版竖切
第一轮不要同时实现所有方向。建议先做：

```text
角色突破槽 -> 战斗中突破 -> 立即进化一张该角色卡牌
```

最小闭环：
* Run 内保存每名角色的局内突破值
* 突破值获取方式可按角色定位不同配置，例如使用所属卡牌、造成 Break、有效治疗、抽牌、击杀、承压
* 悟性影响该角色突破值获取速度
* 角色突破槽满后，从该角色 RunDeck 中随机或稳定提供 `3` 张可进化牌
* 玩家选择 `1` 张进化
* RunDeck 保存卡牌实例成长 / 进化状态
* 进化后卡牌名称、数值、规则文本变化
* 若被选中的卡牌当前在手牌中，立即刷新当前手牌卡面和效果
* 若被选中的卡牌不在手牌中，更新卡牌实例，之后抽到就是进化后的版本

第一版目标是验证：
```text
玩家能否在一场战斗中看到角色突破，并立刻打出变强后的卡牌。
```

## 4. 可保留的后续方向

### 4.1 卡牌绝学化
卡牌不只是静态定义，而是 Run 内可进化的卡牌实例。

示例：
```text
基础掌法 -> 摧心掌 -> 九重摧心掌
九重摧心掌 -> 血煞摧心掌 / 归元摧心掌 / 裂骨摧心掌
```

后续可考虑：
* 卡牌进化阶位
* 分支进化
* 额外词条
* 卡面、名称、费用、规则文本变化
* 绝学牌专属演出

### 4.2 AP 成长与聚合消费
AP 可以在一局内成长，但必须配套能聚合消费的设计，避免后期每回合只是机械打很多张低费牌。

可考虑：
* 高费爆发牌
* X 费牌
* 消耗全部 AP 的终结牌
* AP 转化为其他爆发资源
* 连击阈值后的自动追击
* 多余 AP 自动转化为收益

设计原则：
```text
AP 变多后，玩家应该更能爆发，而不是更累。
```

### 4.3 连锁反应构筑
让战斗爽感来自一串触发，而不只是单次大数字。

可考虑：
* 破防触发追击
* 击杀触发抽牌或返 AP
* 毒伤触发扩散
* 获得护盾触发反击
* 使用同类卡牌第 N 次触发额外效果
* 绝学牌击杀后重复一次或追加全体伤害

### 4.4 事件与奖励改为强化构筑
事件、商店、奖励节点不只给资源，而是提供高影响的改造机会。

可考虑：
* 选择一张牌获得词条
* 选择一个角色立即获得突破值
* 永久增加每回合 AP
* 将某张牌推进到下一进化阶位
* 获得强力副作用，例如伤害翻倍但每战开局受伤

### 4.5 敌人与 Boss 检查爆发窗口
敌人设计不应频繁禁止玩家构筑。

不推荐常用：
* 禁止抽牌
* 禁止连击
* 禁止复制
* 强行增加所有卡牌费用

推荐方向：
* 允许玩家爆发，但要求选择正确窗口
* 普通敌人提供爽感舞台
* 精英敌人检查流派短板
* Boss 改变爆发节奏，而不是封死构筑

## 5. 暂缓进入第一版的方向
以下内容可以保留为主题或后续扩展，但暂不进入第一版硬协议：

* `真气`：当前 EP / 奥义资源尚未决定是否改名或重做，不先固定为真气体系
* `流派熟练度`：掌、剑、毒、阵法等流派尚未正式定义，先不做独立熟练度
* `经脉 / 心法 / 门派 / 魔功`：有武侠味，但先作为奖励包装和后续系统储备
* 每张卡牌显式熟练度条：第一版不做主系统，避免 UI 和存档复杂度过高
* 所有卡牌同时拥有等级、经验、熟练度、词条、进化树：后续再拆分，不一次性全上

第一版可以只记录：
```text
CardInstance.TimesPlayedThisRun
```

这个字段后续可用于：
* 进化分支条件
* 事件条件
* 卡牌详情展示
* 成就式成长

## 6. 需要避免
* 不要只堆数值；卡牌从 10 伤害变成 100 伤害很快会腻
* 不要让成长太平均；玩家需要感觉自己重点培养了某个角色或某张牌
* 不要用敌人强行禁止玩家爽；可以考验爆发窗口，但不要频繁封锁构筑
* 不要让每回合操作量无限膨胀；AP 成长必须配套高费牌、自动触发或资源转化
* 不要在规则层为单张卡、单个敌人写硬编码特例；成长仍要数据驱动

## 7. 后续设计原则
后续改规则时优先遵守：

* 让玩家感觉自己在养成怪物
* 允许中后期构筑明显失控
* 爽感来自成长兑现，而不是单纯降低难度
* 战斗中突破要有即时反馈
* 卡牌进化要改变名称、卡面、数值或规则文本
* UI 必须清楚展示角色和卡牌为什么变强
* 规则仍保持数据驱动，不为单张卡硬写特例
