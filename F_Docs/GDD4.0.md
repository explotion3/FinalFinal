## 1. 战斗总纲
### 1.1 战斗定位
本作是一款以**三人小队协作**为核心的武侠题材回合制卡牌构筑游戏。  
玩家需要在**共享牌组、共享生命、独立压力、敌方先机、Break 窗口与奥义资源**之间持续做决策。

### 1.2 核心系统构成
* 我方 3 名角色，共享牌组、手牌、AP、EP 与队伍总生命
* 每名角色独立拥有压力、专属状态、所属单位相关卡牌判定与成长方向
* 敌方通常由 1~4 名单位组成，各自拥有生命、韧性、意图、先机与状态
* 战斗围绕出牌、控节奏、抢 Break、稳血线、控压力与释放奥义展开

### 1.3 核心体验目标
* 玩家每回合都能明确当前最重要的问题是保命、抢 Break、稳压还是终结
* 敌方压力主要来自意图、先机、连击、状态与高威胁窗口，而不是单纯堆数值
* 我方强度主要体现为角色协作、资源转换与窗口兑现，而不是单张牌裸强度
* 崩溃必须形成真实惩罚，但不能直接剥夺玩家全部操作权

### 1.4 核心决策问题
* 这一回合更应该保命、铺垫、抢节奏还是完成终结
* 现在继续出牌，是否会让关键敌人提前行动
* 当前是否存在值得优先争夺的 Break 窗口
* 哪名角色的崩溃风险最值得优先处理
* EP 现在是否值得投入奥义，还是应该保留给更关键的时点

## 2. 玩家战斗系统
### 2.1 队伍结构
* 每局固定上阵 3 名角色
* 全队共享：队伍生命、AP、EP、手牌、牌库、弃牌堆与遗物收益
* 每名角色独立拥有：压力、状态、被动、专属机制与所属单位相关卡牌判定
* 玩家管理的不是三条独立生命线，而是队伍总血量与三名角色的崩溃风险

### 2.2 生存结构
* 生存结构由**队伍总生命**、**角色生命份额**与**角色压力**共同组成
* 队伍生命承担主要伤害与治疗结算；角色压力负责驱动崩溃与苏醒
* 玩家侧核心公开属性保持精简，重点围绕生命份额、压力上限、攻击、防御、Break 系数、暴击与 EP 系数展开
* 攻击、护盾、治疗与削韧优先采用“角色属性 × 倍率”的统一表达方式

### 2.3 AP 系统
* AP 是回合内的基础操作资源，用于决定这一轮能组织多少动作
* AP 的主要价值在于迫使玩家在输出、防御、过牌、铺垫与抢 Break 之间取舍
* 首版默认 AP 不保留；例外由卡牌、状态或遗物单独定义

### 2.4 EP 与奥义系统
* EP 是队伍共享的奥义资源，不替代 AP，也不属于普通出牌次数
* 奥义用于改写关键回合，重点承担稳场、抢窗口、放大 Break 或完成终结
* 奥义不占手牌、不进入牌库、不参与普通卡牌判定，也不触发先机减少事件
* 奥义必须与角色定位、专属机制和队伍职责直接挂钩，不能退化为单纯大数值按钮

### 2.5 崩溃与苏醒
* 当角色压力达到上限时进入崩溃，崩溃会移除该角色生命份额并把所属手牌临时转化为崩溃卡
* 崩溃卡是惩罚牌，不是新构筑资源；它只保留最低操作权与苏醒推进功能
* 苏醒应由玩家主动推动，并保持简单、稳定、可预判
* 首版不为崩溃与苏醒附加额外正向奖励，避免出现主动吃崩溃换资源的反向利用

### 2.6 角色分工
* 首发角色职责默认围绕破阵、续航、辅助、收割四类展开
* 每名角色必须有明确主职责，可有次职责，但不应设计成万能角色
* 在共享血条结构下，角色分工应优先围绕压力承接、受击收益、稳定削韧、资源支援、爆发兑现与残局收束展开
* 队伍强度应来自互补与联动，而不是三个高强单卡位的简单叠加

### 2.7 角色标准结构
* 标准角色骨架为：3 张基础牌、5 张特有卡、1 个奥义与 1 组技能树补强
* 原型阶段允许局部例外，但这些例外只服务垂直切片，不反向定义正式版标准
* 技能树用于强化角色主轴、补强短板、调整开局风格与放大奥义 / 特有卡价值，但不应额外引入第二套独立玩法

## 3. 敌方战斗系统
### 3.1 敌人结构
* 敌人主要由生命、韧性、意图、先机、状态与类型标签构成
* 敌我不追求完全对称的属性体系
* 普通敌人、精英与首领的主要差异应先体现在节奏压力与机制职责，而不是单纯数值倍数

### 3.2 意图系统
* 敌人每轮公开下一次行动意图，用于给玩家提供拆招依据
* 意图类型以攻击、连续攻击、防御、蓄力、强化、异常施加与召唤为主
* 敌方对玩家侧的伤害默认只结算到队伍总生命；高压体验优先通过高倍率、连击、先机压迫与异常组合实现

### 3.3 先机系统
* 先机是本作最重要的节奏压力系统之一，用来决定敌人何时行动
* 玩家每次打出会推进节奏的牌，都会触发一次先机减少事件；敌人按各自响应值逼近出手点
* 玩家因此必须在“继续连段”和“避免敌人提前插队”之间反复取舍
* 首版默认每个敌人每轮只行动一次；少量特殊敌人可拥有复动、稳固、迅捷等例外特性

### 3.4 Break 系统
* Break 是本作的核心争夺窗口，不只是附属增伤机制
* 攻击造成实际伤害时，默认会按攻击者 Break 系数将部分伤害转化为削韧；少量卡牌与效果可追加独立削韧
* Break 成功后应同时带来节奏收益、输出收益与部分角色、遗物或牌组联动收益
* Break、先机与敌方意图必须形成明确联动，让“抢窗口”成为真实决策

## 4. 战斗内容载体
### 4.1 卡牌
* 牌区默认包括抽牌堆、手牌区、弃牌堆、持续区与消耗区
* 普通攻击牌与技能牌默认进入弃牌堆；能力牌默认进入持续区；不进入普通牌区循环的牌默认进入消耗区
* 崩溃转化只影响角色牌进入手牌时的临时表现，不改写原始卡牌身份

### 4.2 卡牌类型
* **攻击**：以直接伤害、削韧、追击、收割与对敌人生效为主
* **技能**：以防御、恢复、过牌、调度、控场与一次性功能效果为主
* **能力**：以持续到整场战斗结束的被动规则改变为主
* 奥义不属于攻击、技能、能力三类，也不参与普通卡牌联动

### 4.3 特有卡与变体
* 特有卡是角色战斗身份的重要载体，用于承接角色主轴、专属机制与成长分支
* 每名角色标准结构中都包含特有卡，但特有卡本身仍属于卡牌系统的一部分
* 变体的价值应优先体现为机制变化、资源逻辑变化与联动变化，而不是单纯数值放大
* 变体设计应围绕“强化主轴、补足短板、玩法转向”三类方向展开

### 4.4 关键词
* 规则关键词只描述牌的规则性质，不承载增益、减益或角色专属机制
* 首版关键词以 `快速 / 开战 / 唯一 / 保留 / 主导 / 回收X / 消耗` 为主

### 4.5 状态
* 状态系统分为通用正面状态、通用负面状态与角色专属状态三类
* 敌人和角色都用状态栏
* 首版关键通用状态以护体、士气、易伤、虚弱、流血、中毒、腐蚀、灼烧、迟滞、破绽、免疫为主
* 其中 `中毒 / 流血 / 灼烧` 当前只作用于敌方单位；`腐蚀` 当前主要用于玩家侧持续伤害，效果与中毒相同
* 角色专属状态用于承载刀势、药引、猎印等职业差异；`剑阵` 相关内容由沈清弦的衍生牌体系承载

### 4.6 遗物定义
* 遗物系统应收束为“强效果、低数量、重改变玩法”的结构
* 遗物大体分为武学遗物、战术遗物与奇物秘宝三类
* 单件遗物要能改变出牌逻辑，稀有遗物应能形成明确构筑轴
* 遗物文本应保持短、直、可预判，并允许出现显著联动

### 4.7 文本规范
* 卡牌、状态、遗物与奥义文本都必须优先做到短、直、可预判
* 默认按“结果 -> 条件 -> 附加结果 -> 特殊规则”组织表达
* 同类效果保持统一句式，百分比数值优先直接挂接角色属性
* 规则关键词与状态名必须严格分层，不混写

## 5. 单局流程与成长
### 5.1 角色成长入口
* 开局只投入基础牌与 1 张初始特有卡，其余特有卡在单局过程中逐步获得
* 角色成长主要来自特有卡获取、特有卡变体升级、奥义强化、技能树补强与少量遗物 / 事件修正
* 成长节奏应在单局过程中逐步展开：开局展示基础职责，中期建立分支，后期形成完整战斗身份
* 重点不是堆更多通用牌，而是逐步解锁并精进角色武学

### 5.2 地图与节点
* 地图节点以普通战斗、精英战斗、商店、事件、修炼 / 休息与首领战为主
* 普通战斗主要提供常规资源与牌组迭代机会
* 精英战斗用于检验构筑强度，并提供更高价值奖励
* 商店负责主动修正构筑，事件负责高波动抉择，修炼 / 休息负责回血、控压与局部养成调整

### 5.3 事件
* 事件用于提供高风险高收益抉择、增加单局差异，并承接角色成长、流派转向与压力管理
* 事件类型以代价换收益、神秘交易、角色成长、分支顿悟与压力调整为主
* 当事件承担角色成长时，优先使用“三选一”分支结构，避免单局构筑过于稳定
* 所有事件都应明确写清选项、代价与收益；若涉及压力，必须明确作用对象与作用方式
* 压力相关事件应服务于主动控压，而不是只提供额外惩罚

### 5.4 遗物获取途径
* 遗物定义属于战斗内容载体；遗物获取属于单局成长流程
* 单局中，遗物主要通过精英奖励、事件奖励、商店与少量特殊节点进入构筑
* 遗物获取频率应低于普通牌获取频率，但单件遗物的影响力应明显更高
* 高价值遗物获取应始终伴随明显机会成本，避免单局构筑过于平滑

### 5.5 商店
* 商店主要提供买牌、买遗物、删牌、升级与少量消耗品或角色专属补强机会
* 商店是构筑修正点，不是纯数值补给站
* 删牌价值必须长期成立，稀有牌不应过度泛滥，玩家应持续存在“想买但买不起”的张力

### 5.6 装备与背包
* 装备系统不走传统多槽位角色扮演装备方案，首版只保留少量能强化角色风格或提供战术效果的装备位
* 背包系统首版仅保留少量消耗品容量，主模式重点仍放在牌、遗物与节点选择，而不是囤积物资

## 6. 战斗信息设计
### 6.1 战斗关键信息
战斗界面至少需要稳定显示以下信息：
* 队伍总生命、AP、EP
* 三名角色的压力、关键状态、崩溃 / 苏醒进度与奥义可用性
* 手牌、牌堆数量、回合结束按钮与当前目标
* 敌方生命、韧性、先机、意图与关键状态
* 当前选中牌的核心预估结果，如伤害、护盾、回复与削韧

### 6.2 信息优先级
* 第一优先级始终是：敌人下一步做什么、什么时候做、我方能否承受、谁最接近崩溃、当前是否存在 Break 窗口
* 第二优先级是：本回合还能组织多少 AP 连段、哪些牌已满足触发条件、当前更适合救场、铺垫还是保资源

### 6.3 战斗反馈原则
* Break、奥义、AP 返还、EP 增长、追击与连段都必须有清晰即时反馈
* 即将行动的敌人、已行动敌人、濒临崩溃角色与即将苏醒角色都应具备明显提示
* 反馈应优先服务战术判断，而不是只追求演出热闹

### 6.4 状态栏原则
* 状态栏的职责是帮助玩家快速理解当前战斗规则，而不是单纯堆图标
* 默认显示通用正负面状态、角色专属状态与战斗内被动
* 同名状态允许聚合显示，但必须保留持续方式与关键层数信息
* 本场持续状态默认不显示回合数；回合持续状态必须显示剩余回合数
* 战斗内被动应明确标识其所属角色或单位
* 首版排序优先级为：负面状态 -> 角色专属状态 -> 其余状态与被动

## 7. 数值设计框架
### 7.1 核心数值模型
* 首版数值模型采用“角色属性 × 卡牌倍率”结构
* 卡牌文本优先使用百分比、倍率与明确阈值表达
* 玩家、敌人、卡牌、状态、遗物的具体数值应尽量集中维护，避免在多份文档重复抄写
* 本文档只说明数值为什么这样设计，不承载全部测试参数

### 7.2 关键数值轴
* 玩家属性：生命份额、压力上限、攻击、防御、Break 系数、EP 系数
* 敌人参数：生命、韧性、伤害基准、先机值与先机响应
* 卡牌强度：基础牌、初始特有卡、成长牌与终结牌
* 核心资源：AP、EP、Break 奖励、崩溃与苏醒阈值
* 难度分层：普通敌人、精英与首领的节奏差异

### 7.3 调参原则
* 普通战应允许玩家快速读懂牌组节奏与敌人威胁
* 精英战应检验构筑是否已经形成明确主轴
* 首领战应同时检验输出窗口、续航能力与控压能力
* Break、崩溃 / 苏醒、EP 与奥义频率都应可通过数值微调独立控制
* 任何会显著改变战斗节奏的参数，都应优先回写到 `Numbers_FirstPass.md`

## 8. 首版开发范围
### 8.1 文档职责边界
* GDD 只保留系统结构与设计原则
* 具体角色内容维护在 `Starter_Characters.md`
* 具体敌人内容维护在 `Starter_Enemies.md`
* 具体遗物内容维护在 `Starter_Relics.md`
* 具体事件内容维护在 `Starter_Events.md`

### 8.2 首版验证目标
* 垂直切片阶段优先保证至少 3 名角色具备最小可玩集
* 普通战、精英战与首领战都必须能验证核心节奏是否成立
* 首版优先验证共享牌组、压力、先机、Break、奥义、崩溃与苏醒这几条主骨架

### 8.3 后续扩充方向
* 正式扩充内容时，再逐步回填完整特有卡、变体、成长分支与章节池
* 后续新增系统应优先服务现有主骨架，而不是平行增加新的复杂度中心
