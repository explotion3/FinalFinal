# 战斗规则文档

## 1. 文档定位
本文档用于统一战斗中的术语定义、结算时序与判定边界。  
`GDD4.0.md` 负责描述玩法设计、系统目标与范围边界；`Combat_Data_Schema_v2.md` 负责描述字段结构与运行时承载方式；本文档负责描述“战斗中具体如何判定”。

---

## 2. 核心术语

### 2.1 实际伤害
实际伤害指某次伤害结算在经过伤害倍率、暴击、易伤、减伤、护盾抵消等处理后，最终成功结算到目标生命值上的伤害数值。  
仅实际伤害可用于触发“按伤害转化削韧”等后续判定。

### 2.2 实际生命损失
实际生命损失指队伍总生命值在一次受击事件中实际减少的数值。  
被护盾、免伤、减伤完全抵消的部分，不计入实际生命损失。  
实际生命损失用于压力转化与部分受击收益判定。

### 2.3 实际回复量
实际回复量指一次治疗或回复效果中，真正恢复到队伍当前生命值上的数值。  
溢出治疗不计入实际回复量。  
实际回复量用于战斗内的间接减压判定。

### 2.4 独立受击事件
独立受击事件指一次单独成立的伤害结算。  
多段攻击、连续攻击、追击分别视为多个独立受击事件。  
敌方不设计“对我方全体造成伤害”这一类攻击，因此不存在“全体攻击拆成多个受击对象”的判定。

### 2.5 卡牌全部效果结算完毕
卡牌全部效果结算完毕，指该牌文本写明的伤害、护盾、治疗、抽牌、返 AP、附加状态、额外削韧、生成牌等结果都已完成处理。  
正式版中，敌方先机变化默认在这一时点之后统一结算。

### 2.6 先机减少事件
先机减少事件是推动所有存活敌人先机值下降的一次统一事件。  
默认情况下：
* 每打出 1 张普通牌，在该牌全部效果结算完毕后，触发 1 次先机减少事件
* 每打出 1 张崩溃卡，在该牌全部效果结算完毕后，触发 1 次先机减少事件
* 奥义不触发先机减少事件
* 带 `快速` 关键词的牌默认跳过本次先机减少事件，除非文本明确写出其他处理

### 2.7 Break
Break 指敌方韧性值降至 0 后进入的破绽状态。  
Break 可打断或延后敌方行动，并为玩家提供额外收益。

### 2.8 崩溃
崩溃指某名角色压力条达到上限后进入的失衡状态。  
崩溃会带来两类结果：
* 该角色生命份额暂时移出队伍最大生命
* 该角色进入手牌的所属卡牌临时转化为崩溃卡

### 2.9 苏醒
苏醒指崩溃角色脱离崩溃状态并恢复正常操作权。  
首版中，固定计数苏醒为主，小概率直接苏醒为低频例外。

## 3. 单张牌结算顺序

### 3.1 普通牌默认顺序
1. 确认打牌条件合法
2. 支付该牌的实际 AP 消耗
3. 结算该牌文本中的全部效果
4. 结算由该牌引发的即时状态变化
5. 若该牌本次会触发先机减少事件，则结算该牌对应的先机减少事件
6. 若有敌人先机归零，则将其放入行动队列
7. 处理该牌去向

### 3.2 第 3 步包含的常见内容
第 3 步“结算该牌文本中的全部效果”通常包括：
* 伤害
* 护盾
* 治疗
* 抽牌
* 弃牌
* 返 AP
* 施加或移除状态
* 额外削韧
* 生成牌
* 其他文本明确写出的即时收益

### 3.3 中途不插入敌人行动
默认情况下，敌人不会在一张牌的多段伤害、中途抽牌、返 AP、附加削韧或其他中间效果之间插队行动。  
敌方行动检查发生在该牌全部效果结算完毕之后。

### 3.4 目标合法性与失效规则
以下为首版默认目标规则；若卡牌文本明确写出其他处理，则以文本为准。

* 只有文本明确要求选择目标的牌或效果，才在打出前检查目标合法性
* 合法目标指仍在当前战斗中、符合目标阵营、并满足该牌文本条件的单位
* 若打出前不存在任何合法目标，则该牌默认不能打出，并按 `无合法目标` 处理
* 若一张牌包含多个效果段，则每个需要目标的效果段在实际结算到该段时再次检查目标是否合法
* 若某个效果段结算时原目标已失效，则该效果段默认结算失败；不依赖该目标的其他效果段继续结算
* 目标失效默认包括：目标已被击败、已离开当前战斗、或已不再满足该效果的文本条件
* 默认不因目标失效而自动重新指定目标，除非文本明确写出“重新指定”“改为随机目标”或其他替代处理
* 随机目标在该效果段实际结算时，从当前全部合法目标中选择；若此时没有合法目标，则该效果段结算失败
* 不需要指定单位目标的效果，不受 `无合法目标` 规则影响
* `全体`、`自身`、`全队` 这类固定作用范围效果，默认在其作用范围内分别检查是否仍有可结算对象；无可结算对象的子目标直接跳过

## 4. 伤害、治疗与压力

### 4.1 伤害结算
1. 敌方或我方造成一次伤害
2. 先结算暴击、易伤、减伤、护盾抵消等修正
3. 得到实际伤害或实际生命损失
4. 再触发基于“实际伤害 / 实际生命损失”的后续规则

#### 4.1.1 玩家共享生命伤害保护
当前 Runtime 已有最小 incoming team HP damage protection 协议，用于处理 `生命免疫` 这类玩家侧共享生命保护状态。`免疫` 仍是“抵消或忽略特定负面效果”的上位概念，当前只落地了共享生命 HP damage protection 子类。

玩家侧受到伤害时，当前顺序为：
1. 先由 `TeamShield` 抵消总伤害
2. 剩余会穿透护盾的部分形成 pending Team HP damage
3. 再读取 `team_player` 上的状态保护，按 `IncomingTeamHealthDamageReductionPercentPerStack` 抵消 pending Team HP damage
4. 保护后的实际 Team HP damage 才扣除 `TeamCurrentHP`
5. 只有实际 `TeamCurrentHP` 下降时，才触发 `OwnerTookHealthDamage`、`PlayerTeamTookHealthDamage` 等基于实际生命损失的窗口

若保护状态完全抵消本次 pending Team HP damage，则本次不产生实际生命损失，也不会触发霍断岳“受压得刀势”等受生命伤害触发。
同理，护心铜镜这类 `PlayerTeamTookHealthDamage` 遗物也不会在生命免疫完全抵消 HP damage 时触发。

### 4.2 压力转化顺序
敌人攻击玩家时，默认按以下顺序处理：
1. 伤害结算到队伍总生命
2. 护盾与共享生命伤害保护结算后，得到本次独立受击事件的实际生命损失
3. 将该实际生命损失按压力规则换算
4. 为本次独立受击事件随机选择一名合法角色承担压力
5. 结算随机保护

### 4.3 压力转化粒度
压力转化以“每次独立受击事件”为单位结算。  
多段攻击、连续攻击、追击中的每一段都分别独立换算压力，并分别独立选择合法目标。

### 4.4 治疗与减压顺序
治疗玩家时，默认按以下顺序处理：
1. 先恢复队伍总生命
2. 计算实际回复量
3. 再根据实际回复量换算减压
4. 随机选择一名合法角色承接本次减压

### 4.5 溢出治疗
若队伍当前生命已满，或治疗量超过可恢复上限，则超出部分不计入实际回复量，也不产生减压。

## 5. Break 与先机

### 5.1 攻击转削韧
造成实际伤害的攻击段，默认追加：

`本次实际伤害 × 攻击者 Break 系数`

若牌面还带有额外削韧，则与上式叠加结算。  
由伤害转化而来的削韧默认受单段上限约束。

### 5.2 Break 的触发时点
Break 在单张牌的效果结算过程中即时检查。  
也就是说，若某段伤害或额外削韧已经使敌方韧性归零，则该敌人可在该牌尚未完全结算前进入 Break 状态。

### 5.3 Break 与先机的先后
正式版默认顺序为：
1. 先结算单张牌的伤害与削韧
2. 检查是否触发 Break
3. 该牌全部效果结算完成
4. 若该牌本次会触发先机减少事件，再触发先机减少事件
5. 再检查敌人是否因先机归零而行动

这意味着：  
Break 的打断优先于同一张牌结算完成后的先机插队判定。

### 5.4 同时 Break 与同时归零先机的优先级
若多个敌人因同一张牌或同一次事件同时发生状态变化，正式版按**站位顺序**处理。

默认规则如下：
* 多个敌人同时进入 Break：按站位顺序依次结算 Break 结果
* 多个敌人同时因先机减少事件归零：按站位顺序依次进入行动队列
* 多个敌人同时满足 Break 与先机归零条件时，先按站位顺序处理 Break，再处理行动队列检查
* 若某敌人在进入行动队列前已因 Break 被判定取消本轮行动，则其不进入本轮行动队列

若未来存在特殊敌人或首领明确写出例外，则以文本为准。

### 5.5 Break 条件效果
当前 Runtime 已把 effect requirement 收口到 `Effect.Conditions[]`。第一阶段支持 `HandCard / TargetState / ConsumedStatus / ConsumedGeneratedCard` 四类对象化条件，并由 `FinalBattleEffectExecutionService` 在效果执行前统一判定。  
Break 判定只读取敌方权威状态中的 `CurrentBreakValue <= 0`，不新增第二套 Break 真相。  
若 condition 不满足，该效果段跳过且不产生副作用；同一张牌或奥义中的其他效果段继续按原顺序结算。

## 6. 状态结算窗口原则

### 6.1 设计原则
状态不应各自随意定义结算时点，而应统一挂接到少量固定的“状态结算窗口”上。  
这样可以降低理解成本，也能避免新增状态时不断制造新的判定例外。

### 6.2 推荐窗口类型
正式版建议优先使用以下几类窗口：
* 回合开始窗口
* 玩家结束回合后的敌方行动前窗口
* 单位行动后窗口
* 条件触发窗口

### 6.3 条件触发窗口
条件触发窗口用于承载非持续跳伤类效果，例如：
* 受击时
* 打牌时
* Break 时
* 崩溃时
* 苏醒时

### 6.4 当前约束
状态的具体结算时点允许在数值测试中调整，但必须始终挂接到固定窗口上，而不是临时新增新的独立时点。  
首版先采用一套默认映射，后续如需调整，也应只在既有窗口之间移动。

### 6.5 首版默认状态时点表
以下时点为当前原型的默认映射：

* **灼烧**：当前只作用于敌方单位；在敌方回合开始窗口结算
* **中毒**：当前只作用于敌方单位；在玩家结束回合后的敌方行动前窗口结算
* **腐蚀**：当前主要作用于玩家侧；效果与中毒相同；在玩家结束回合后的敌方行动前窗口结算
* **流血**：当前只作用于敌方单位；在敌方单位行动后窗口结算
* **护体**：常驻修正状态，不单独跳伤，在受击时参与减伤计算
* **士气**：常驻修正状态，不单独跳伤，在造成伤害时参与攻击修正
* **易伤**：常驻修正状态，在目标受到伤害时参与伤害放大
* **虚弱**：常驻修正状态，在目标造成伤害时参与伤害降低
* **破绽**：条件收益状态，在满足 Break、追击、处决等文本条件时参与判定
* **迟滞**：先机干预状态，在先机变化或敌方行动检查时参与判定
* **专属状态**：默认优先挂接到条件触发窗口；若为持续型状态，再按各自文本接入固定窗口

### 6.6 状态结算的一般顺序
当同一窗口内需要同时结算多个状态时，默认按以下顺序处理：
1. 先结算高危负面持续效果
2. 再结算一般持续效果
3. 最后结算由状态引发的附加收益、转化或移除

若多个同类状态同时存在，则默认按站位顺序与状态添加顺序处理。

### 6.7 持续伤害的数值来源
持续伤害类状态默认按施加者的主输出属性计算。

默认规则如下：
* 当前首版的 `中毒 / 流血 / 灼烧` 只作用于敌方单位，默认按施加者的 `Attack` 计算
* `腐蚀` 当前主要用于玩家侧持续伤害，效果与 `中毒` 相同，默认按施加者的 `Attack` 计算
* 若后续开放敌方施加持续伤害到玩家侧，再单独补敌方持续伤害口径
* 若文本明确写出固定值、独立倍率或其他例外，则以文本为准

### 6.8 共享血条下的玩家侧状态边界
在共享血条结构下，玩家侧状态默认分为“队伍共享状态”和“角色个人状态”两类。

* 队伍共享状态默认挂在 `team_player`
* 角色个人状态默认挂在对应角色的运行时单位
* 同一状态在首版默认只采用一种主归属，不同时支持“同名状态既能挂队伍又能挂角色”的混合用法，除非文本明确写出例外

#### 6.8.1 队伍共享状态
以下类型的玩家侧状态，默认按队伍共享状态处理：

* 直接作用于队伍共享生命的持续伤害、持续治疗、减伤、增伤承受或免疫效果
* 直接修正队伍共享生命变化结果的状态
* 明确作用于 `全队`、`队伍`、`共享生命` 或其他队伍公共对象的状态

首版默认示例：
* `护体 / 易伤 / 免疫`：若作用于玩家侧并直接修正共享生命相关判定，则默认挂在 `team_player`
* `腐蚀`：若作用于玩家侧共享生命，默认挂在 `team_player`
* `中毒 / 灼烧 / 流血` 当前不作用于玩家侧，因此不挂在 `team_player`

#### 6.8.2 角色个人状态
以下类型的玩家侧状态，默认按角色个人状态处理：

* 只影响某个角色出牌、伤害、治疗、削韧或其他主动行为的状态
* 只影响某个角色压力、崩溃、苏醒、受击承压、专属机制或奥义判定的状态
* 只作用于该角色所属牌、该角色专属机制或该角色专属资源的状态

首版默认示例：
* `士气 / 虚弱`：默认挂在实际造成效果的角色身上，并在该角色结算相关牌或行为时生效
* `刀势 / 药引`：默认挂在对应角色身上，不挂到 `team_player`
* `剑阵` 属于沈清弦的衍生牌体系，不作为状态挂载

#### 6.8.3 结算优先原则
当一次效果同时涉及共享血条与角色个人状态时，首版默认按以下原则处理：

1. 先确定这次效果影响的是共享对象还是角色个人对象
2. 先结算共享生命相关状态修正，再得到本次实际生命变化
3. 再根据实际生命变化结算压力、崩溃、苏醒等角色个人结果
4. 只影响角色主动行为的状态，不回头改写已经完成的共享生命结算结果

#### 6.8.4 文本归属默认规则
当文本没有明确写出状态挂载对象时，首版默认按以下方式判断：

* 若文本关注“队伍受到伤害 / 队伍回复 / 全队获得 / 共享生命变化”，默认挂到 `team_player`
* 若文本关注“该角色打出 / 该角色受到压力 / 该角色崩溃 / 该角色苏醒 / 该角色的牌”，默认挂到对应角色
* 若文本同时包含两层影响，则优先将状态挂在触发主体上，实际影响结果再按文本结算到共享对象或角色对象

## 7. 崩溃与苏醒

### 7.1 崩溃触发时点
当某名角色压力条达到上限时，该角色立即进入崩溃。  
崩溃一经触发，立刻执行：
* 移除该角色生命份额
* 压缩队伍最大生命
* 当前手牌中的该角色牌转化为崩溃卡

### 7.2 崩溃卡转化规则
崩溃卡是手牌阶段的临时形态，而不是永久替换。  
规则如下：
* 崩溃瞬间，当前手牌中的所属牌立即转化
* 该角色崩溃期间，其原始卡牌在进入手牌时继续转化
* 该角色苏醒后，当前手牌中的崩溃卡立即恢复为原牌

### 7.3 崩溃卡默认结算
崩溃卡默认：
* 不消耗 AP
* 不回复 EP
* 提供苏醒计数 +1
* 有小概率直接苏醒
* 在全部效果结算完毕后触发 1 次先机减少事件

### 7.4 苏醒默认判定
首版苏醒以递增计数为主：
* 每打出 1 张该角色崩溃卡，苏醒计数 +1
* 达到当前阈值后立即苏醒
* 当前阈值按单角色当前累计崩溃次数读取
* 首次崩溃阈值为 3，第二次为 5，第三次及之后封顶为 7
* 小概率直接苏醒仅作为低频例外，不改变“递增计数为主”的主结构

#### 7.4.1 小概率直接苏醒
为避免随机性压过主闭环，首版采用保守概率：
* 距离当前苏醒阈值剩余 **2 次及以上** 时：**0%**
* 距离当前苏醒阈值剩余 **1 次** 时：**10%**
* 苏醒计数达到当前阈值时：**不再判概率，直接苏醒**

这意味着首版的主要体验仍然是“按当前阈值逐步打出崩溃卡完成苏醒”，而不是依赖随机跳过流程。

### 7.5 苏醒后的结果
角色苏醒时立即结算：
* 脱离崩溃状态
* 压力重置到安全值
* 恢复该角色生命份额
* 当前手牌中的崩溃卡恢复为原牌
* 当前生命值不自动恢复

### 7.6 跨战斗保留
首版中，角色的崩溃相关进度默认**跨战斗保留**。

默认规则如下：
* 若角色在一场战斗结束时仍处于崩溃，则进入下一场战斗时继续保持崩溃
* 该角色的 `CurrentStress`、`CurrentAwakenCount`、`CollapseCount` 默认一并保留
* 下一场战斗中的苏醒阈值继续按保留后的 `CollapseCount` 读取，不在开战时重置
* 继续保持崩溃的角色，在下一场战斗开始时仍然：
  * 不可释放奥义
  * 进入手牌的所属牌继续转化为崩溃卡
  * 对应生命份额继续不计入队伍最大生命
* 只有在后续战斗中实际完成苏醒后，才恢复正常操作权与生命份额

## 8. 牌区、生成、复制与消耗区规则

### 8.1 牌区默认去向
首版正式牌区包括抽牌堆、手牌区、弃牌堆、持续区与消耗区。

* 普通攻击牌与技能牌结算后默认进入弃牌堆
* 能力牌结算后默认进入持续区
* 带 `消耗` 或 `消灭` 规则的牌，结算后默认进入消耗区
* 若文本明确写出其他去向，则按文本结算

### 8.2 手牌上限与回合结束整理
手牌上限由规则配置提供，首版默认值为 `10`。

* 回合结束时，先执行通常弃牌流程
* 带 `保留` 规则的牌，不因通常弃牌流程离开手牌
* 若完成通常弃牌流程后手牌仍超过上限，超出部分按后续实现决定弃置；本文当前不定死具体选择方式

### 8.3 抽牌堆耗尽与重洗
当需要抽牌而抽牌堆不足时，首版默认按以下顺序处理：

* 先将弃牌堆洗回抽牌堆
* 再继续执行剩余抽牌
* 持续区与消耗区中的牌默认不参与重洗
* 若抽牌堆与弃牌堆都为空，则剩余抽牌失败

### 8.4 生成牌
生成牌默认必须在生成时就确定所属单位。

* 若文本明确写出由某单位生成，则默认归属于该单位
* 若文本未明确写出，则默认归属于触发该效果的单位
* 若生成的是不预设所属的通用牌，则必须在生成时指定所属单位
* 生成牌进入手牌、抽牌堆、弃牌堆、持续区或其他牌区后，均按其所属单位参与后续判定

### 8.5 复制牌
复制牌默认复制的是“原牌定义 + 永久成长结果”，而不是临时战斗修正。

* 复制牌默认保留原牌的所属单位
* 复制牌默认继承原牌的升级、变体与永久强化结果
* 复制牌默认不继承本场战斗中临时获得的伤害加成、费用修正、一次性附魔或其他临时数值修正，除非文本明确写出
* 带有“唯一”规则的牌，默认不能被复制成功

### 8.6 消耗区找回
首版默认不允许任意从消耗区取回牌。

* 只有文本明确写出“从消耗区返回”时，才允许找回
* 若无明确文本，消耗区中的牌默认不再参与普通牌区循环
* 从消耗区返回的牌，回到指定牌区后仍保留原有所属单位与永久成长结果
* 当前 Runtime 使用通用 `MoveCards` effect 表达牌区迁移；“消耗 1 张手中的衍生剑阵牌”是 `Hand -> ConsumePile` 的特例，而不是独立专用效果

### 8.7 崩溃卡与上述规则的关系
崩溃卡不是独立卡种，而是原牌在手牌阶段的临时表现形态。

* 默认不直接生成崩溃卡
* 默认不复制崩溃卡本身，而是复制其对应原牌
* 默认不从消耗区找回“崩溃卡形态”，只能找回其对应原牌
* 若对应角色仍处于崩溃，则该原牌在再次进入手牌时继续转化为崩溃卡

### 8.8 关键词运行规则
以下为首版默认关键词运行规则；若卡牌文本明确写出其他处理，则以文本为准。

* `快速`：见 `2.6 先机减少事件` 与 `9.3 玩家出牌阶段`；带 `快速` 的牌默认跳过本次先机减少事件
* `开战`：见 `9.1 战斗开始初始化`；带 `开战` 的牌在开局抽牌前先处理置顶，再参与初始抽牌
* `保留`：见 `8.2 手牌上限与回合结束整理`；带 `保留` 的牌不因通常弃牌流程离开手牌
* `唯一`：见 `8.5 复制牌`；带 `唯一` 的牌默认不能被复制成功
* `消耗`：见 `8.1 牌区默认去向` 与 `8.6 消耗区找回`；带 `消耗` 的牌结算后直接进入消耗区
* `主导`：每回合开始时进入待判定状态；若本回合玩家从手牌主动打出的第一张牌带有 `主导`，则在该牌其他效果结算前先触发其主导效果；无论是否触发成功，本回合的主导判定只进行一次
* `回收X`：带 `回收X` 的牌在结算后若默认去向为弃牌堆，则先进入弃牌堆，再立刻回到手牌，并将 `X-1`；当 `X` 降为 `0` 时，清除该关键词

**补充说明**
* 当前第一版由 `FinalBattleCardService` 统一解释 `Retain / Expend`：模板与衍生牌实例都默认继承 `CardDefinition.Keywords`，`GenerateCardEffect` 不再重复持有 `Retain / Consume` 布尔覆写
* `回收X` 只覆盖“先入弃牌堆再回手”的默认流程；若文本明确写出进入持续区、消耗区或其他去向，则按文本结算
* `主导` 只检查本回合第一张由玩家主动打出的手牌；由效果自动生成、复制或直接打出的牌，不自动占用或重置该判定，除非文本明确写出

## 9. 回合流程

### 9.1 战斗开始初始化
1. 读取本场战斗对应的遭遇模板与规则配置
2. 以当前永久构筑结果建立本场战斗的初始牌组
3. 初始化抽牌堆、手牌区、弃牌堆、持续区与消耗区
4. 默认情况下，可用牌先进入抽牌堆；持续区与消耗区开战时默认为空，除非文本明确写出其他进入方式
5. 处理带 `开战` 关键词的牌：将其置于抽牌堆顶，并在开局抽牌阶段优先被抽入手牌
6. 执行初始抽牌
7. 若某角色因跨战斗保留而继续处于崩溃，则其所属牌在进入初始手牌时立即转化为崩溃卡
8. 初始化完成后，进入首回合开始

**补充说明**
* 多张 `开战` 牌同时存在时，默认保持其原有相对顺序
* 能力牌不会因开战自动进入持续区，仍需正常抽到并打出后才进入持续区
* 当前 Runtime 已落地：初始牌组进入抽牌堆后会先洗牌，再将带 `开战` 关键词的牌置于抽牌堆顶，最后执行初始抽牌

### 9.2 回合开始
1. 我方恢复基础 AP
2. 我方按 `BattleRuleConfig.TurnStartDrawCount` 固定抽牌
3. 所有存活敌人刷新本轮状态
4. 所有敌人获得本轮初始先机值
5. 敌人显示本轮意图

**补充说明**
* `TurnStartDrawCount` 与 `InitialHandSize` 分离：前者用于每个玩家回合开始固定抽牌，后者只用于战斗初始化抽牌
* 当前 Runtime 不再按“补到 N 张手牌”处理回合开始抽牌；若手中保留了牌，仍会额外抽取固定数量的牌

### 9.3 玩家出牌阶段
1. 玩家打出一张牌
2. 完整结算该牌效果
3. 若该牌本次会触发先机减少事件，则触发先机减少事件
4. 检查敌人是否进入行动队列
5. 若有敌人行动，则依序结算
6. 玩家继续操作，直到主动结束回合或无法继续操作

### 9.4 回合结束
1. 结算玩家结束回合后的敌方行动前窗口效果
2. 所有本轮尚未行动的敌人依序行动
3. 结算回合结束触发
4. 进入下一轮

**补充说明**
* 当前 Runtime 已落地：回合结束时会先执行通常弃牌流程，非 `保留` 手牌进入弃牌堆，`保留` 牌继续留在手牌
