# 卡牌设计规范

## 1. 文档定位

本文档用于统一卡牌内容设计规范。

它负责说明：

- 一张卡牌应包含哪些设计字段。
- 卡牌所属、类型、稀有度、关键词与文本应如何书写。
- 卡牌在 Run 内强化、进化、绝学化时，哪些内容可以变化，哪些内容默认不应变化。
- 角色升级成长三选一中的卡牌进化候选应如何设计。

本文档不负责维护具体角色卡组清单，也不负责定义底层数据结构字段。底层结构以 `Combat_Data_Schema_v2.md` 为准，模块职责以 `Code_Function_Requirements.md` 为准。

## 2. 基础对象与成长边界

卡牌设计默认区分三层对象：

```text
CardDefinition：静态卡牌模板
RunCardInstance：本次 Run 中玩家实际拥有的某一张牌
BattleCardInstance：本场战斗 / 当前手牌中的临时卡牌实例
```

设计原则：

- `CardDefinition` 只描述静态模板，不在 Run 中被回写。
- `RunCardInstance` 承接本局内的卡牌成长，例如进化、绝学化、强化槽与强化珠。
- `BattleCardInstance` 承接战斗内临时修正，例如本回合费用变化、临时伤害提高、临时保留等。
- 卡牌成长默认通过 `BaseCardId / CurrentCardId` 表达。
- `BaseCardId` 表示这张牌最初是什么招式。
- `CurrentCardId` 表示这张牌当前使用哪一套规则、名称和文本。

跨角色即时改卡也属于 `BattleCardInstance` 层的临时修正。卡牌可以通过 `ApplyCardModifiers` 修改其他友方当前手牌实例，但这类效果不回写 Run 卡牌，不影响后续新抽入手的牌，除非效果文本和 schema 明确另有持续追踪规则。

示例：

```text
BaseCardId = 裂锋
CurrentCardId = 裂锋·破势
```

玩家应能感受到这张牌是从普通招式练出来的，而不是凭空替换成另一张无关卡牌。

## 3. 卡牌标准字段

卡牌条目统一包含以下字段：

- 名称：玩家可见的卡牌名称。
- CardId：数据层唯一标识。
- 所属单位：该牌默认服务的角色或单位。
- 类型：攻击牌、技能牌、能力牌等。
- 费用：打出这张牌需要消耗的 AP 或其他资源。
- 稀有度：描述静态模板的内容级别。
- 关键词：正式规则词。
- 标签：用于内容筛选、进化候选、奖励池、强化珠适配等。
- 文本：玩家可见的牌面效果。
- 备注：仅供设计说明，不进入正式牌面文本。

补充规则：

- 玩家可见文本应尽量短。
- 数据实现需要的复杂条件不一定全部写入牌面，但核心触发条件必须可预判。
- 标签不等于关键词。标签服务设计与筛选，关键词服务正式规则。

## 3.1 Card Text Style v0.1

卡牌 `RulesText` 采用“短语化 + RichText 标签 + 每行一个效果”的卡面文本规范。  
首版目标是提升战斗速读性，并为后续图标化和动态数值投影留下稳定格式；本规范不改变规则结算。

### 允许的首版标签

| 标签          | 用途       | 示例                                |
| ----------- | -------- | --------------------------------- |
| `<num>`     | 普通数值     | `<num>2</>`、`<num>100%</>`        |
| `<stat>`    | 属性来源     | `<stat>攻击力</>`、`<stat>防御力</>`     |
| `<status>`  | 状态或资源名   | `<status>刀势</>`、`<status>中毒</>`   |
| `<keyword>` | 关键词或牌类短词 | `<keyword>保留</>`、`<keyword>剑阵</>` |
| `<cost>`    | AP / 费用  | `<cost>1 AP</>`                   |
| `<good>`    | 正向变化     | `<good>+20%</>`                   |
| `<bad>`     | 负向变化     | `<bad>-1</>`                      |

### 基础句式

伤害统一写成：

```text
造成 <stat>攻击力</> <num>100%</> 伤害。
造成 <num>2</> 段 <stat>攻击力</> <num>45%</> 伤害。
造成 <num>6</> 伤害。
```

护盾、治疗、削韧统一写成：

```text
获得 <stat>防御力</> <num>80%</> 护盾。
回复 <num>5</> 共享生命。
额外 <num>2</> 削韧。
```

资源型状态获得可用短写；普通状态仍保留动词：

```text
+<num>1</> <status>刀势</>。
+<num>1</> <status>药引</>。
获得 <num>1</> <status>锋锐</>。
施加 <num>2</> <status>中毒</>。
```

消耗、条件、改卡统一写成：

```text
消耗 <num>1</> <status>刀势</>：额外 <num>2</> 削韧。
若手中有 <keyword>剑阵</> 牌：抽 <num>1</> 张牌。
其他友方当前手牌攻击牌：-<cost>1 AP</>，<good>20%</> 最终伤害。
```

关键词集中写在一行：

```text
<keyword>衍生</>、<keyword>保留</>、<keyword>消耗</>。
```

### 禁止回退的旧写法

Starter 卡牌文本不再使用以下格式：

```text
对目标造成相当于攻击力 100% 的伤害。
获得相当于防御力 80% 的护盾。
获得 1 层刀势。
额外造成 2 点削韧。
100%ATK / BaseDamagePower
```

Editor validator 对 starter 卡牌中的明显旧格式给 warning；首版不把这类问题升为 error，避免阻断临时测试资产。

## 4. 卡牌所属与判定

卡牌所属用于确定这张牌当前按哪个单位结算，并服务哪一类内容结构。

### 4.1 角色卡

角色卡默认所属单位为某个角色。

职责：

- 承接角色战斗身份。
- 承接角色专属机制。
- 承接角色成长路线。
- 作为角色升级进化候选的主要来源。

示例：

```text
霍断岳牌：削韧、承压、Break 爆发、刀势
叶半夏牌：治疗、药引、稳压、保护
沈清弦牌：剑阵、过牌、连锁、重排
```

### 4.2 通用卡

通用卡静态模板可以不预设所属单位，但进入卡组、生成或复制时必须确定当前所属单位。

规则：

- 通用卡打出时，默认使用其当前所属单位的属性。
- 通用卡参与当前所属单位可用的联动判定。
- 通用卡不应直接替代角色卡的身份作用。

### 4.3 衍生牌

衍生牌由卡牌、状态或其他效果生成，不作为普通卡池主体。

规则：

- 衍生牌默认服务当前回合或当前战斗。
- 衍生牌不是稀有度概念。
- 衍生牌生成时也应确定所属单位。

### 4.4 所属变化边界

默认不建议在卡牌成长中改变所属角色。

允许的例外：

- 合击牌。
- 特殊剧情牌。
- 明确说明为跨角色协作的特殊卡牌。

普通进化与绝学化应保留原始所属，以保证角色成长、突破值、进化候选和 UI 归属稳定。

## 5. 卡牌类型

正式卡牌类型统一为：

### 5.1 攻击牌

用于承载直接进攻、伤害与削韧类效果。

常见职责：

- 造成伤害。
- 推进 Break。
- 对 Break 目标追加收益。
- 完成击杀与收割。

### 5.2 技能牌

用于承载防御、治疗、辅助、资源修正与功能效果。

常见职责：

- 获得护盾。
- 回复生命。
- 抽牌或整理手牌。
- 回复 AP。
- 降低压力。
- 施加或移除状态。

### 5.3 能力牌

用于承载持续生效的规则效果或整场被动效果。

常见职责：

- 改变整场出牌逻辑。
- 强化角色主轴。
- 提供长期被动收益。

补充规则：

- 同一张牌应尽量只归入一种大类型。
- 若一张牌同时具备伤害与功能，应按主要职责判定类型。
- 普通强化不应改变卡牌大类型。
- 进化通常不改变大类型。
- 绝学化可以在少数特殊情况下改变定位，但仍应保留 `BaseCardId` 身份。

## 6. 稀有度与成长阶段

卡牌稀有度统一为：

- 普通：基础构筑内容与最常见的卡牌层级。
- 稀有：更强或更有方向性的卡牌层级。
- 罕见：构筑指向更明确的高价值卡牌层级。
- 传说：最稀缺、最具代表性或最能改变构筑方向的卡牌层级。

重要规则：

- 稀有度描述静态模板的内容级别。
- 稀有度不等同于 Run 内成长阶段。
- 普通卡也可以在 Run 内进化或绝学化。
- 高稀有度不代表文本必须更长。
- 高稀有度不代表可以脱离系统边界单独超模。

成长阶段建议另行表达：

```text
基础卡 -> 进化卡 -> 绝学卡
```

示例：

```text
普通卡 裂锋
可以在 Run 中进化为 裂锋·破势
后续再绝学化为 裂锋·血战绝式
```

## 7. 关键词

关键词描述卡牌的正式规则性质。

当前通用关键词口径：

- 快速：打出时不会触发本次先机减少事件。
- 开战：进入战斗时置于抽牌堆顶，并在开局抽牌阶段优先抽入手牌。
- 唯一：一般作用于能力牌；不可被复制。
- 保留：回合结束时不会因通常弃牌流程离开手牌。
- 主导：每回合开始进入待判定状态；若本回合主动打出的第一张牌带有该关键词，则触发其主导效果。
- 回收X：从手牌打出并结算后，先进入弃牌堆，再立刻回到手牌，并将 `X-1`；当 `X` 降为 `0` 时，清除该关键词。
- 消耗：结算后直接进入消耗区，不进入弃牌堆，也不参与普通牌区循环。

补充规则：

- 关键词只写正式规则词。
- 状态名、资源名、流派标签和设计备注不直接写成关键词。
- 没进入统一词表的词，不先写成正式关键词。
- `临界`、`Break`、`刀势`、`药引`、`剑阵` 等可以作为资源、状态或标签，但是否成为关键词需要单独确认。

## 8. 卡牌成长与可变化范围

卡牌成长允许改变的内容包括：

- 数值：伤害、治疗、护盾、削韧、状态层数等。
- 费用：费用降低、费用提高但效果增强、条件性费用变化等。
- 词条：新增或强化正式关键词。
- 触发条件：Break、击杀、临界、上一张牌、当前资源等。
- 资源互动：AP、压力、临界、刀势、药引、剑阵、奥义等。
- 目标规则：单体、全体、随机、溅射、击杀后转移等。
- 区域行为：保留、消耗、回到抽牌堆、抽到时触发等。
- 表现层：卡名、卡框、卡面、音效、战斗日志、演出。
- 强化槽结构：槽数量、槽级、可镶嵌方向。

默认不建议改变的内容：

- 所属角色。
- 卡牌大类型。
- `BaseCardId`。
- 这张牌的基础身份。

示例：

```text
裂锋 可以从普通削韧攻击进化为 Break 爆发牌。
但它仍应被识别为 裂锋 系列，而不是变成一张无关治疗牌。
```

## 9. 强化、进化与绝学化

### 9.1 强化

强化是卡牌细节成长。

定位：

```text
让这张牌更好用，但不改变它的身份。
```

常见变化：

- 数值提高。
- 状态层数提高。
- 小型条件收益。
- 小型资源收益。
- 后续可由强化珠承担。

强化不应成为第一版主系统。第一版可暂不实现完整强化珠与强化槽。

### 9.2 进化

进化是卡牌机制成长。

定位：

```text
让这张牌从普通招式变成某个流派组件。
```

常见变化：

- 增加触发条件。
- 增加角色资源互动。
- 改变部分费用规则。
- 提高或改变强化槽结构。
- 明确该牌后续成长方向。

示例：

```text
裂锋
造成伤害，削韧 2。

裂锋·破势
造成伤害，削韧提高。
若本牌造成 Break，获得刀势。
```

### 9.3 绝学化

绝学化是高阶进化。

定位：

```text
让这张牌成为本局可以围绕构筑的核心武学。
```

绝学牌应满足至少一项：

- 强绑定 Break。
- 强绑定临界。
- 强绑定 AP 或资源循环。
- 强绑定角色专属机制。
- 具备明显高光触发条件。
- 拥有专属名称和表现。

示例：

```text
裂锋·血战绝式
若霍断岳处于临界，本牌额外触发一次。
若本牌击杀敌人，回复 AP 或降低压力。
```

## 10. 进化候选设计规则

角色升级时会触发成长三选一。卡牌进化候选是其中一种候选类型。

设计规则：

- 进化候选优先来自该角色所属 `RunCardInstance`。
- 候选文本必须明确写出 `From -> To`。
- 候选必须说明核心变化点。
- 同一次候选中，尽量避免三个选项都是纯数值提高。
- 候选应尽量围绕玩家已经使用、强化或符合角色路线的卡牌生成。
- 绝学化候选只应在卡牌已进化，并满足等级、属性、使用次数或其他条件后出现。

推荐三类进化方向：

### 10.1 即时强度

当前马上变强，适合稳定推进。

示例：

```text
裂锋 -> 裂锋·破势
伤害与削韧提高，造成 Break 时获得刀势。
```

### 10.2 成长潜力

当前效果变化不大，但后续成长空间更高。

示例：

```text
裂锋 -> 裂锋·藏锋
效果基本不变，但强化槽结构提高。
```

### 10.3 流派转向

让这张牌进入新的构筑路线。

示例：

```text
裂锋 -> 裂锋·血战
临界期间获得额外收益，适合高压反杀路线。
```

## 11. 强化槽与强化珠设计口径

强化槽与强化珠属于后续扩展系统，不作为第一版必须实现内容。

方向规则：

- 不设置强化珠背包。
- 获得强化珠时，立即选择一张可用卡牌镶嵌，或跳过换补偿。
- 一个强化槽只能放一个强化珠。
- 强化槽有槽级。
- 强化珠有珠阶与珠级。
- 槽级限制可镶嵌的珠阶。
- 同一张卡上 3 个同名同珠级珠自动合成为更高珠级。
- 合成后珠阶不变，仍只占一个槽。
- 第一版不要求实现强化珠、槽级、珠阶、珠级、三合一。

示例：

```text
裂锋
槽位：1 / 1

裂锋·藏锋
效果基本不变
槽位：2 / 2 / 1

裂锋·纳元
效果基本不变
槽位：3 / 1
```

设计重点：

- 槽位型进化应提供成长潜力。
- 高级槽不应过早大量出现。
- 强化珠不应完全替代卡牌本体。
- 珠子应强化卡牌定位，而不是把所有牌变成万能牌。

## 12. 文本规范

卡牌文本统一遵守以下要求：

- 短：文本尽量精简，避免无效描述。
- 直：文本直接描述效果，不绕弯解释。
- 可预判：文本应让玩家明确预期这张牌会产生什么结果。

书写规则：

- 先写主要效果，再写附加效果。
- 优先使用明确倍率、百分比与阈值表达。
- 不把状态名和关键词混写。
- 同一张牌尽量不要承担过多层条件链。
- 已在类型或关键词字段中表达的信息，不在文本中重复书写。
- 进化候选文本应明确写出变化点。
- 绝学文本应优先表达构筑价值，不堆过长条件链。

常用句式：

```text
对目标造成相当于攻击力 X% 的伤害。
获得相当于防御力 X% 的护盾。
回复 X% 生命份额血量。
回复 X AP。
生成 1 张某牌到手牌。
若不满足条件，则不能打出此牌。
若满足条件，则触发结果。
```

进化候选句式：

```text
裂锋 -> 裂锋·破势
削韧提高。若本牌造成 Break，获得刀势。
```

绝学化候选句式：

```text
裂锋·破势 -> 裂锋·血战绝式
临界期间额外触发一次。击杀时回复 AP。
```

## 13. 第一版范围

第一版重点：

- 静态卡牌字段规范。
- 所属单位与结算口径。
- 卡牌类型与文本规范。
- `RunCardInstance` 的 `BaseCardId / CurrentCardId` 成长口径。
- 角色升级成长三选一中的卡牌进化候选。
- 基础卡 -> 进化卡 的最小闭环。
- 当前手牌中被进化卡牌的即时刷新。

第一版暂不要求：

- 完整强化珠系统。
- 强化珠即时镶嵌流程。
- 强化槽槽级与珠阶限制。
- 同卡同名珠三合一。
- 珠子背包、拆卸、洗词条、套装。
- 所有卡牌完整绝学树。
- 随机词条拼接。
- 角色专属临界收益牌组。
